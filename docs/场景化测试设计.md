# 场景化调度测试

## 1. 目标

`schedbench` 保留为调度器微基准，用于快速检查策略切换、抢占和统计接口。
`schedscene` 提供面向应用场景的负载，用于比较不同调度策略在具体工作模式下的表现。

场景测试位于 `schedworkloads/`，与内核调度实现、原有微基准保持独立。

```text
schedworkloads/
├── scene.h                 公共类型、默认参数和 workload 接口
├── scene_main.c            参数解析、创建任务和回收任务
├── scene_workloads.c       计算、文件读写、交互式短任务
├── scene_metrics.c         结构化结果输出
├── xv6_runner.py           QEMU 启动、结果解析、CSV 和汇总
└── run-scenes.py           宿主机实验入口
```

## 2. 场景定义

### 计算密集型

每个任务执行多轮大规模整数哈希计算，任务之间不主动阻塞。
该场景关注 CPU 时间分配、公平性和整体吞吐量。

### I/O 密集型

每个任务创建独立文件，连续写入多个 512 字节数据块，随后重新打开文件读取并校验，
最后删除临时文件。该场景使用 xv6 文件系统和 virtio 磁盘路径，关注阻塞、唤醒和
I/O 任务的周转时间。

### 混合交互型

任务按 `compute -> io -> interactive` 循环分配：

- `compute` 执行大规模计算；
- `io` 执行文件写入、读取和删除；
- `interactive` 执行少量短文件操作，模拟需要快速响应的前台任务。

该场景关注短任务响应延迟，以及前台任务与后台任务并行运行时的整体表现。

## 3. 参数

宿主机脚本提供统一参数：

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `--policies` | `SCHED_RR` | 逗号分隔的编译期调度策略 |
| `--scenarios` | `compute,io,mixed` | 要运行的场景 |
| `--jobs` | `6` | 每个场景创建的子任务数 |
| `--work` | `20` | 场景工作规模 |
| `--repeat` | `1` | 每个策略、场景的重复次数 |
| `--compute-priority` | `1` | 计算任务优先级 |
| `--io-priority` | `9` | I/O 任务优先级 |
| `--interactive-priority` | `12` | 交互任务优先级 |
| `--output` | 无 | CSV 输出路径，不设置时输出到终端；只传 `--output` 时按所选算法写入 `results/schedscene-<algorithms>.csv` |

`work` 在计算场景中表示计算轮数，在 I/O 场景中表示写入的数据块数。
交互任务保持短任务特征，最多执行 8 轮短文件操作。

## 4. 运行方式

先验证三个场景：

```bash
cd ~/XV6/XV6-RISCV-OPT
python3 schedworkloads/run-scenes.py \
  --policies SCHED_RR \
  --scenarios compute,io,mixed \
  --jobs 6 \
  --work 20 \
  --repeat 1
```

对比三种策略并保存结果：

```bash
python3 schedworkloads/run-scenes.py \
  --policies SCHED_RR,SCHED_STATIC_PRIORITY,SCHED_MLFQ \
  --scenarios compute,io,mixed \
  --jobs 6 \
  --work 20 \
  --repeat 3 \
  --output results/schedscene-rr-spq-mlfq.csv
```

只测试综合场景：

```bash
python3 schedworkloads/run-scenes.py \
  --policies SCHED_RR,SCHED_STATIC_PRIORITY,SCHED_MLFQ \
  --scenarios mixed \
  --jobs 6 \
  --work 20 \
  --compute-priority 1 \
  --io-priority 9 \
  --interactive-priority 12 \
  --repeat 3 \
  --output results/schedscene-mixed-rr-spq-mlfq.csv
```

每种策略对应独立镜像，QEMU 固定使用 `CPUS=1`。脚本先检查
`build/policies/<policy>/` 下的镜像；镜像存在时直接启动，缺失时才执行对应的
Make 目标进行构建。脚本会在输出文件的父目录不存在时自动创建，并在每次构建或
运行结束后清理中间产物。

手动构建策略镜像：

```bash
make rr
make spq
make mlfq
```

生成的文件分别为：

```text
build/policies/rr/kernel-rr
build/policies/rr/fs-rr.img
build/policies/spq/kernel-spq
build/policies/spq/fs-spq.img
build/policies/mlfq/kernel-mlfq
build/policies/mlfq/fs-mlfq.img
```

如果修改了内核、调度器或用户程序，需要强制刷新策略镜像：

```bash
make policies-clean
```

## 5. 输出指标

场景测试与 `schedbench` 使用同一组调度指标，包括周转时间、带权周转时间、用户态
响应延迟、内核响应延迟、运行 tick、就绪等待时间、调度次数和吞吐量。

CSV 额外包含：

```text
scenario   compute-heavy / io-heavy / mixed-interactive
kind       compute / io / interactive
```

建议按 `policy + scenario + kind` 分组计算平均值，重点观察：

- `compute-heavy`：`cpu_share`、`run_ticks`、`throughput`
- `io-heavy`：`turnaround`、`wait_count`、`total_ready_time`
- `mixed-interactive`：`response`、`kernel_response`、短任务周转时间
