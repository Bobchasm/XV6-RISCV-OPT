# 三种调度算法测试检查清单

本清单用于验证 `RR`、静态优先级队列 `SPQ` 和 `MLFQ` 三种调度算法，
重点是保证三种算法使用相同的负载、相同的任务数量、相同的工作量和相同的
CPU 数量，再比较调度行为和性能指标。

约定：

- `RR` 的编译策略为 `SCHED_RR`，构建目标为 `make rr`；
- `SPQ` 的编译策略为 `SCHED_STATIC_PRIORITY`，构建目标为 `make spq`；
- `MLFQ` 的编译策略为 `SCHED_MLFQ`，构建目标为 `make mlfq`；
- 性能对比默认固定 `CPUS=1`，避免多核调度噪声影响结果；
- 所有命令默认在仓库根目录 `XV6/XV6-RISCV-OPT` 执行；
- `--output` 单独出现时，脚本会按算法名生成结果文件，例如
  `results/schedbench-rr-spq-mlfq.csv`。

```bash

make policies-clean
```

## 2. 三种策略构建检查

### 2.1 分别构建策略镜像

策略镜像构建目标内部会执行 `make clean`，因此必须串行执行。推荐直接使用
`make policies`；不要把 `make rr`、`make spq` 和 `make mlfq` 放到同一个并行
构建命令或后台任务中。

- [ ] 一次构建三种策略镜像。

```bash
make policies
```

- [ ] 构建 RR。

```bash
make rr
```

- [ ] 构建 SPQ。

```bash
make spq
```

- [ ] 构建 MLFQ。

```bash
make mlfq
```

- [ ] 确认三种策略都生成独立镜像，且没有使用过长或混淆的旧名称。

```bash
find build/policies -maxdepth 2 -type f -print | sort
```

预期至少包含：

```text
build/policies/rr/kernel-rr
build/policies/rr/fs-rr.img
build/policies/spq/kernel-spq
build/policies/spq/fs-spq.img
build/policies/mlfq/kernel-mlfq

```

- [ ] 重复执行构建，确认已有镜像会被复用。

```bash
make policies
```

输出中应出现 `reuse rr image`、`reuse spq image` 和 `reuse mlfq image`。

### 2.2 编译策略宏检查

- [ ] 检查三个策略确实使用不同的编译期策略值，而不是只复制同一个镜像。

```bash
make -n rr 2>&1 | rg 'SCHED_DEFAULT_POLICY|kernel-rr'
make -n spq 2>&1 | rg 'SCHED_DEFAULT_POLICY|kernel-spq'
make -n mlfq 2>&1 | rg 'SCHED_DEFAULT_POLICY|kernel-mlfq'
```

预期分别出现：

```text
SCHED_DEFAULT_POLICY=SCHED_RR
SCHED_DEFAULT_POLICY=SCHED_STATIC_PRIORITY
SCHED_DEFAULT_POLICY=SCHED_MLFQ
```

## 3. 基础启动与回归测试

- [ ] 用默认 RR 内核启动 QEMU，确认能进入 xv6 shell。

```bash
make qemu CPUS=1
```

进入 shell 后输入：

```text
echo boot-ok
```

看到 `boot-ok` 后使用 `Ctrl-a x` 退出。

- [ ] 运行 xv6 快速回归测试。

```bash
./test-xv6.py -q usertests
```

- [ ] 运行完整回归测试。

```bash
./test-xv6.py usertests
```

- [ ] 对三种策略分别执行快速回归测试。每次切换策略时使用对应的镜像路径：

```bash
make qemu CPUS=1 \
  KERNEL=build/policies/rr/kernel-rr \
  FS_IMAGE=build/policies/rr/fs-rr.img
```

在 QEMU shell 中输入：

```text
usertests -q
```

然后用 `Ctrl-a x` 退出，再分别替换为 `spq` 和 `mlfq` 的镜像路径。

判定标准：

- 能正常启动并进入 shell；
- `usertests -q` 输出 `ALL TESTS PASSED`；
- 没有出现 `panic`、卡死、QEMU 异常退出或无法回收进程。

## 4. 系统调用和监控检查

- [ ] 验证 `set_prio`、`get_psinfo` 和 `sys_stat` 的基本功能。

```bash
make qemu CPUS=1 \
  KERNEL=build/policies/rr/kernel-rr \
  FS_IMAGE=build/policies/rr/fs-rr.img
```

进入 xv6 shell 后执行：

```text
schedinfo
schedinfo 1
```

检查输出至少包含：

- 进程 PID、名称和状态；
- `priority`；
- `queue` 或队列层级；
- `slice` 或剩余时间片；
- `run_ticks`、就绪次数、等待次数；
- 全局进程数量和调度统计。

- [ ] 使用同一组命令分别检查 SPQ 和 MLFQ，确认系统调用在三种算法下都能工作。

- [ ] 检查非法 PID 或非法参数不会导致内核崩溃。可在 shell 中执行：

```text
schedinfo 0
```

如果用户程序对错误输入有明确返回路径，应记录返回值；如果没有专门的非法
参数测试程序，则至少确认内核没有 `panic`。

## 5. 调度微基准对比

### 5.1 单次三策略对比

- [ ] 使用相同的任务数、工作量和优先级运行三种算法。

```bash
python3 scripts/run-schedbench.py \
  --policies SCHED_RR,SCHED_STATIC_PRIORITY,SCHED_MLFQ \
  --jobs 6 \
  --work 40 \
  --cpu-priority 1 \
  --io-priority 9 \
  --mixed-priority 5 \
  --repeat 1 \
  --output
```

默认结果文件应为：

```text
results/schedbench-rr-spq-mlfq.csv
```

- [ ] 确认 CSV 文件存在且包含表头。

```bash
head -n 3 results/schedbench-rr-spq-mlfq.csv
```

- [ ] 确认结果包含三种策略和三类任务。

```bash
python3 - <<'PY'
import csv
from collections import Counter

path = "results/schedbench-rr-spq-mlfq.csv"
with open(path, newline="") as stream:
    rows = list(csv.DictReader(stream))

print("rows:", len(rows))
print("policies:", Counter(row["policy"] for row in rows))
print("kinds:", Counter(row["kind"] for row in rows))
required = {
    "policy", "kind", "turnaround", "weighted_turnaround", "response",
    "kernel_response", "throughput", "run_ticks", "schedule_count",
}
missing = sorted(required - set(rows[0])) if rows else sorted(required)
print("missing:", missing)
assert not missing
assert {row["policy"] for row in rows} == {
    "SCHED_RR", "SCHED_STATIC_PRIORITY", "SCHED_MLFQ"
}
PY
```

```bash
python3 schedworkloads/run-scenes.py \
```

### 6.2 场景结果检查

- [ ] 确认每个场景结果都包含三种策略。

```bash
python3 - <<'PY'
import csv
from pathlib import Path

for path in sorted(Path("results").glob("schedscene-*-rr-spq-mlfq.csv")):
    with path.open(newline="") as stream:
        rows = list(csv.DictReader(stream))
    policies = {row["policy"] for row in rows}
    print(path, "rows=", len(rows), "policies=", sorted(policies))
    assert policies == {"SCHED_RR", "SCHED_STATIC_PRIORITY", "SCHED_MLFQ"}
PY
```

- [ ] 检查三类负载的关注指标：

| 场景 | 重点指标 | 预期观察 |
|---|---|---|
| `compute` | `cpu_share`、`run_ticks`、`throughput` | RR 更接近公平轮转，SPQ 更体现静态优先级，MLFQ 对长任务逐步降级 |
| `io` | `turnaround`、`response`、`wait_count` | 观察睡眠/唤醒后的响应和等待行为 |
| `mixed` | `response`、`kernel_response`、`turnaround` | 观察短交互任务与后台任务同时存在时的响应差异 |

这里只记录实验观察，不预设某个算法在所有指标上都必须胜出。结论必须结合
负载类型、优先级配置、重复实验的均值和波动解释。

## 8. 边界和稳定性检查

- [ ] 单任务运行，排除多任务竞争导致的偶然现象。

```bash
python3 scripts/run-schedbench.py \
  --policies SCHED_RR,SCHED_STATIC_PRIORITY,SCHED_MLFQ \
  --jobs 1 --work 40 --repeat 3 \
  --output results/schedbench-rr-spq-mlfq-jobs1.csv
```

- [ ] 高并发任务运行，检查进程表、等待和回收路径。

```bash
python3 scripts/run-schedbench.py \
  --policies SCHED_RR,SCHED_STATIC_PRIORITY,SCHED_MLFQ \
  --jobs 12 --work 40 --repeat 3 --timeout 300 \
  --output results/schedbench-rr-spq-mlfq-jobs12.csv
```

- [ ] 三种策略都重复执行，确认不会出现随机 `panic`、卡死、僵尸进程
  或 QEMU 进程残留。

```bash
pgrep -af qemu-system-riscv64 || true
```

- [ ] 检查 CSV 中不存在空字段、负数 tick 或除零产生的异常值。

```bash
python3 - <<'PY'
import csv
from pathlib import Path

numeric = {
    "turnaround", "weighted_turnaround", "response", "kernel_response",
    "throughput", "run_ticks", "schedule_count", "total_ready_time",
}
for path in Path("results").glob("sched*.csv"):
    with path.open(newline="") as stream:
        rows = list(csv.DictReader(stream))
    for row in rows:
        for field in numeric:
            value = float(row[field])
            assert value >= 0, (path, field, value)
    print("validated", path, len(rows))
PY
```

## 9. 结果分析与交付检查

- [ ] 每种算法至少有一次单次实验和三次重复实验结果。
- [ ] 三种算法使用相同的 `jobs`、`work`、CPU 数量和场景参数。
- [ ] 报告同时提供均值和波动范围，不只展示单次最好结果。
- [ ] 至少比较周转时间、带权周转时间、用户态响应延迟、内核响应延迟、
  吞吐量、运行 tick、调度次数和就绪等待时间。
- [ ] 分别讨论 RR、SPQ、MLFQ 的优势、劣势和适用负载，不把 MLFQ
  默认描述成所有指标都最优。
- [ ] 记录异常实验，包括超时、QEMU 崩溃、CSV 解析失败和重复运行差异过大。
- [ ] 保留原始 CSV、命令行参数、工具链版本和测试日期。
- [ ] 报告中的算法名称统一使用 `RR`、`SPQ`、`MLFQ`，内部宏可注明
  `SCHED_STATIC_PRIORITY`。
- [ ] 只提交源码、脚本和文档，不提交 `build/`、`results/`、QEMU 原始日志
  和 Python 缓存。
