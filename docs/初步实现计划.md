# 初步实现计划

## 1 选题

> 实践平台：XV6-RISC-V
>
> 选题：MLFQ多级反馈队列调度优化与进程监控

针对XV6原生简单时间片轮转（RR）调度算法公平性差、无法区分交互/后台进程、响应效率低的问题，重构内核调度框架，实现三级多级反馈队列（MLFQ）抢占式调度，新增进程优先级动态调控、防饥饿晋升机制，配套开发自定义系统调用实现进程状态可视化监控，完成RR、静态优先级、MLFQ三种算法的性能对比分析。

核心功能需求包括：

- 扩展PCB进程控制块，新增优先级、队列层级、剩余时间片、运行时长、状态统计等字段

- 实现三级MLFQ调度规则：高优先级队列短时片、低优先级队列长时片，支持CPU抢占

- 完善调度逻辑：时间片耗尽降级、IO阻塞进程唤醒升级、全局定时晋升防进程饥饿

- 实现必要的自定义系统调用：set_prio（动态改优先级）、get_psinfo（查询进程详情）、sys_stat（全局内核状态统计）等

- 新增调度日志，可视化展示进程切换、抢占、队列升降级全过程

- 设计混合负载测试用例，统计周转时间、带权周转时间、响应延迟，完成多算法性能对比

## 2 基线系统平台

XV6 的调度框架采用简化版的 Round Robin（RR）策略。其核心流程可以概括为：

1. 进程创建后进入就绪队列；
2. 调度器从就绪队列中选择下一个可执行进程；
3. 进程运行一个时间片后触发时钟中断；
4. 内核在时钟中断中记录当前进程状态，并将其重新放回就绪队列；
5. 调度器再挑选下一个进程执行。

是一个典型的“就绪队列 + 时间片轮转 + 抢占式切换”模型。当前进程在执行期间，若时间片耗尽，CPU 会在中断中发生上下文切换；如果进程主动睡眠、等待 I/O 或终止，也会发生状态切换。

同时，调度相关逻辑主要集中在进程管理结构、时钟中断处理和进程切换函数中。当前实现中，所有进程大体处于同一调度平面，运行时长和优先级没有明显区分；因此，调度器不会根据任务特征动态调整执行顺序。

这意味着当前系统在处理交互型任务、后台任务和 CPU 密集型任务时，调度表现较为平均，无法体现更合理的任务分层管理。

当前 XV6 具备基础的多任务支持，但仍属于“单层公平调度”模式。存在问题：

- 算法公平性差、无法区分交互/后台进程；
- 对 I/O 绑定型任务与 CPU 密集型任务没有差异化处理；
- 交互任务的及时响应不足；
- 低优先级任务可能长期被延迟；
- 进程状态统计和调度观测能力不足。

本选题需要在其基础调度框架上增加更细粒度的调度策略，使其由平等轮转向分层优先调度演进。

## 3 初步设计

### 3.1 调度架构设计

为对比分析 RR、静态优先级、MLFQ的性能，在现有的就绪队列和时钟中断基础上增加统一的调度策略抽象，使用**策略模式**。核心思想：

- 共享统一的进程状态字段；
- 统一调度入口；
- 不同调度算法通过不同的选择函数实现；
- 运行时切换策略，以便比较 RR、静态优先级和 MLFQ 的性能差异。

将支持三种调度策略：

- RR：按时间片轮转选择下一个就绪进程
- Static-Priority：按静态优先级排序选择
- MLFQ：按队列层级和时间片规则动态选择

其中，RR 作为基线算法，保留原有调度行为；静态优先级模拟“优先级分层”的简化策略；MLFQ 则作为最终的优化目标。

### 3.2 调度策略切换

采用代码中全局策略变量切换方案，具体为：

- 内核中定义统一枚举：`SCHED_RR`、`SCHED_STATIC_PRIORITY`、`SCHED_MLFQ`；
- 调度模块中定义全局变量 `current_sched_policy` 作为当前生效策略；
- 调度器入口根据该变量调用对应的选择函数；
- 测试时直接修改该变量值，即可切换 RR、静态优先级和 MLFQ；
- 默认策略在内核启动时按编译期宏指定，运行阶段也可通过调试入口切换。

三种算法共享同一套 PCB 字段和调度框架，仅在 `select_next_proc()` 的具体实现不同。该设计保证三种算法在同一内核中共存，便于进行性能对比测试。


### 3.3 PCB 扩展与公共字段设计

扩展 `struct proc` 中的公共字段，确保三种调度算法共享基础状态，并在此基础上扩展各自需要的额外信息：

- priority：当前优先级；
- queue_level：当前队列层级；
- time_slice：当前时间片剩余量；
- run_time：累计运行时间；
- ready_count：就绪次数；
- wait_count：等待次数；
- state_stat：进程状态统计；
- sched_policy：当前生效的调度策略。

其中：

- RR 主要依赖 time_slice 和状态切换；
- 静态优先级重点利用 priority；
- MLFQ 需要 priority、queue_level、time_slice 以及状态统计字段；
- 三种算法共享大量公共字段，不需要三套完全不同的进程结构。

### 3.4 算法实现

#### 3.4.1 RR

RR 算法保持 XV6 原有思路：

- 进程在就绪队列中轮转；
- 每个进程运行一个固定时间片；
- 时间片耗尽后重新入队；
- 不考虑任务性质差异。

#### 3.4.2 静态优先级调度

静态优先级调度在 RR 基础上加入优先级概念：

- 每个进程有一个固定优先级；
- 调度器优先选择高优先级进程；
- 同优先级之间仍然使用轮转。

该方案简单，便于实现，但难以适应任务行为变化，更适合作为中间对照组。

#### 3.4.3 MLFQ

MLFQ 用于最终实现目标：

- 高优先级队列时间片最短；
- 低优先级队列时间片较长；
- 运行时间耗尽后自动降级；
- I/O 唤醒后提升优先级；
- 低优先级任务通过定时晋升避免饥饿。

通过这些策略，调度器能够优先响应交互型任务，并控制后台任务的 CPU 占用。

### 3.5 调度器

调度器实现方式确定为统一入口 + 策略分离：

- `select_next_proc()`：根据当前策略返回下一条执行的进程；
- `update_proc_after_tick()`：在时钟中断中更新时间片和状态；
- `boost_or_downgrade()`：用于 MLFQ 的优先级提升和降级；
- `sched_policy_switch()`：切换当前调度算法。

调度器分为三层逻辑：

1. 公共调度框架：处理就绪队列、时钟中断和上下文切换；
2. 算法选择逻辑：RR、静态优先级、MLFQ 分别实现自己的选择规则；
3. 统计与监控逻辑：记录运行时间、队列变化和调度日志。

三种算法共用同一套基本调度机制，仅在选择逻辑不同，便于实现和实验比较。

### 3.6 系统调用与监控设计

为了支持调度对比和进程状态观察，新增三个系统调用：

1. set_prio：允许动态修改某个进程优先级；
2. get_psinfo：查询进程状态与调度信息；
3. sys_stat：返回全局调度统计信息。

同时，系统中还将加入调度日志，用于记录：

- 进程切换；
- 时间片耗尽；
- 优先级升级/降级；
- 抢占事件；
- 队列变化。

### 3.7 性能对比方案

在完成基础功能后，我们将设计 CPU-heavy、I/O-heavy 和混合负载三类任务，统计：

- 周转时间；
- 带权周转时间；
- 响应时间；
- 吞吐量；
- 调度次数。

通过对 RR、静态优先级和 MLFQ 的实验结果进行对比，验证：

- RR 作为公平基线；
- 静态优先级提高了部分任务选择性；
- MLFQ 在交互型和混合负载场景下表现更优。
