# 中期工作说明

> 实践平台：XV6-RISC-V
> 
> 选题：MLFQ多级反馈队列调度优化与进程监控

## 1 目标

基于 XV6-RISC-V，围绕调度策略优化和进程运行状态监控，计划完成：

- 在 XV6 原有 RR 调度基础上引入策略模式，统一调度入口和进程状态管理；
- 实现 RR、静态优先级和 MLFQ 三种调度策略，支持策略切换和对比实验；
- 扩展 PCB，记录优先级、队列层级、时间片、运行时间及状态统计；
- 重点实现 MLFQ 的多级队列、时间片降级、唤醒升级和防饥饿机制；
- 增加 `set_prio`、`get_psinfo`、`sys_stat` 等系统调用，支持进程信息查询；
- 设计 CPU 密集型、I/O 密集型和混合型负载，统计周转时间、带权周转时间、响应延迟、吞吐量等指标；
- 三种策略性能对比

## 2 中期已完成

### 2.1 调度框架

- 采用策略模式重构调度器；
- 通过 `函数指针` 实现 `多态` 统一 `select_next_proc`、时钟记账、进程唤醒和抢占接口；
- 保留 RR 作为默认调度策略；
- 支持通过编译参数选择默认策略；
- 使不同策略共享同一套 PCB 字段和调度流程。

### 2.2 PCB 与调度状态

已在进程控制块中加入并维护以下信息：

- 进程优先级；
- MLFQ 队列层级；
- 剩余时间片；
- 累计运行时间；
- 就绪次数和等待次数；
- 就绪等待时间；
- 各进程状态统计；
- 当前调度策略。

### 2.3 调度策略

- 完成 RR 策略模块化接入；
- 完成静态优先级调度初步实现，同优先级进程采用轮转；
- 完成 MLFQ 初步实现：
  - 三级队列；
  - 队列时间片为 `1/2/4` 个 tick；
  - CPU 密集型进程使用完整时间片后降级；
  - 睡眠唤醒进程提升一级；
  - 就绪等待达到阈值后触发老化提升；
  - 高优先级进程到达时支持抢占。

### 2.4 系统调用与监控

已实现：

- `set_prio`：设置指定进程的优先级；
- `get_psinfo`：查询进程状态和调度信息；
- `sys_stat`：查询全局进程及调度统计。

同时增加了 `schedinfo` 用户程序，用于验证系统调用和输出调度状态。

### 2.5 测试与工程支持

- 增加统一的 `schedbench` 用户态测试负载；
- 支持 CPU、I/O、混合三类任务；
- 支持终端/文件输出 CSV 数据；
- 已加入周转时间、带权周转时间、响应延迟和吞吐量统计；
- 保留调度测试与系统代码的模块边界；
- 修复测试脚本中的 QEMU 进程回收、shell 启动等待和管道异常处理；
- `usertests -q` 通过；

## 3 后续计划

### 3.1 完善 MLFQ

- 检查多级队列在不同负载下的调度行为；
- 校准时间片、老化阈值和唤醒升级规则；
- 完善抢占边界和多核运行稳定性；
- 通过监控数据验证降级、升级和防饥饿机制。

### 3.2 完善监控指标

- 精确记录进程首次获得 CPU 的时间；
- 区分用户态响应延迟和内核调度响应时间；
- 增加调度次数、实际运行时间、等待时间等指标；
- 统一指标定义、字段命名和 CSV 输出格式。

### 3.3 完成性能实验

- 使用相同任务数量、工作量和 CPU 数量测试三种策略；
- 分别测试 CPU 密集型、I/O 密集型和混合型负载；
- 多次运行实验，记录平均值和必要的波动范围；
- 对比周转时间、带权周转时间、响应延迟、吞吐量和调度次数；
- 分析 RR、静态优先级和 MLFQ 的适用场景与性能差异。
